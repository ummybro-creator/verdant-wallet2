1. How to generate a payment link
You can generate a payment link dynamically for your users by sending a simple GET request to your API endpoint. The response will be in JSON format.

GET https://rspayment.shop/api.php?amount=500&user_id=INR70438&order_id=TXN123456789&ext=MyGamePay&webhook_url=https://yourdomain.com/webhook.php&return_url=https://yourdomain.com/success.php
 IMPORTANT NOTE FOR user_id:
The user_id parameter is your Merchant ID provided by our gateway (Your ID: INR70438).

DO NOT pass your player's or app user's dynamic ID here. It must always be your fixed Merchant ID. Passing an invalid ID will result in a payment generation error.
Parameters:

amount : The deposit amount in INR (Min: ₹200).
user_id : (Mandatory) Your fixed Merchant ID (e.g. INR70438).
order_id : A unique transaction ID generated by your system (e.g. TXN123456789). MUST be unique for every transaction.
ext : (Optional) Custom extension string or app name. Defaults to 'SimplePay'.
webhook_url : The webhook URL where payment success notifications will be sent in JSON format.
return_url : The URL where the user will be sent back after successful payment.
2. API Responses (JSON format)
Depending on the parameters you send, our API will return a JSON response. Here are the common responses you should handle in your frontend or backend.

✅ 2.1 Success Response
When the link is successfully created, extract `data.payUrl` and redirect the user.

{
  "status": "success",
  "message": "Payment link generated successfully.",
  "data": {
    "merchant_order_id": "TXN12FF3456789",
    "platform_order_id": "1784269683880422848",
    "payUrl": "https://pay.done-wallet.com/DN1ardorx1qr?theme=2",
    "amount": 500
  }
}
❌ 2.2 Error: Order ID Already Exists
If you send an `order_id` that you have already used previously.

{
  "status": "error",
  "message": "Unable to create payment order.",
  "gateway_response": {
    "status": 0,
    "message": "merchantOrderId repeated error"
  }
}
❌ 2.3 Error: Invalid Merchant ID
If the `user_id` parameter does not match your registered Merchant ID.

{
  "status": "error",
  "message": "Invalid Merchant ID (user_id). You are not authorized to create a payment link."
}
3. HTML Example (Frontend Implementation)
If you are triggering this via JavaScript (AJAX/Fetch), here is how you might handle the JSON response to redirect the user:

fetch('https://rspayment.shop/api.php?amount=500&user_id=INR70438&order_id=TXN1234&webhook_url=...&return_url=...')
  .then(response => response.json())
  .then(data => {
    if (data.status === 'success') {
       // Redirect user to the payment link
       window.location.href = data.data.payUrl;
    } else {
       // Show error alert
       alert("Error: " + data.message);
    }
  });
4. Handling Webhook / Callback Response
Once the payment is marked as successful, an automated background POST request will be sent to the webhook_url you provided.

Data you will receive via JSON POST:

status : 'success'
user_id : Your Merchant ID (e.g. INR70438).
merchant_order_id : The same unique `order_id` you passed during link creation.
amount : The exact amount paid.
Example PHP Backend Implementation (webhook.php):

<?php
// Capture incoming JSON POST parameters from Gateway
$raw_post_data = file_get_contents('php://input');
$data = json_decode($raw_post_data, true);

$status = $data['status'] ?? '';
$userid = $data['user_id'] ?? '';
$merchant_order_id = $data['merchant_order_id'] ?? '';

if ($status === 'success' && !empty($userid) && !empty($merchant_order_id)) {
    // 1. Database verification logic goes here
    // 2. Credit the amount to user wallet based on merchant_order_id

    echo "SUCCESS"; // Acknowledge the payment response
} else {
    echo "INVALID_REQUEST";
}
?>
